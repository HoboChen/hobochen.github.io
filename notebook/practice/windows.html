Enterprise 系列包括 Enterprise、Enterprise LTSC、IoT LTSC；功能面接近，差异主要在更新策略、生命周期、授权和设备用途。

出处：

  • Windows 11 版本对比
  • Hyper-V on Windows
  • Dev Drive
  • ReFS
  • LTSC 2024 新特性

  • IoT Enterprise 概览
  • IoT LTSC 2024 生命周期

更新策略

  • Insider：Canary → Dev → Beta → Release Preview，预览通道。
  • Home / Pro：GA Channel，年度功能更新；Home 控制能力最弱，Pro 可短期暂停和用策略做基础延迟。
  • Enterprise：GA Channel，但可通过 Intune / WSUS / Windows Update for Business 控制节奏。
  • Enterprise LTSC：只收安全 / 质量更新；Windows 11 Enterprise LTSC 2024 支持 5 年；内置应用支持范围比 GA Channel 小，Edge 仍是默认浏览器。
  • IoT LTSC：只收安全 / 质量更新；Windows 11 IoT Enterprise LTSC 2024 支持 10 年；面向固定功能设备，IoT 文档强调 removable packages 和 kiosk / restricted user experience。

手动安装和配置

  • Git：运行 git lfs install；Git for Windows 自带 GCM，认证配置见 Git
  • WSL：见 Ubuntu WSL Setup，进入 Ubuntu 后执行 Linux General 的 P0 bootstrap
  • 输入法：小狼毫 + 白霜拼音
  • TeX / CJK 字体：winget 没有稳定的 TeX Live ID；需要 PDF 输出时安装 TeX Live 和 Noto Serif CJK SC，或在 WSL 中使用 Linux General 的 TeX 包；也可按项目改用 MiKTeX / TinyTeX
  • ca-certificates：Windows 使用系统信任存储，WSL 内按 Linux General 安装
  • Adobe Creative Cloud
    • Lightroom Classic
  • DaVinci Resolve
  • iCloud / Apple Devices / Apple Music
  • Elgato 4K Capture Utility

关闭

  • 关闭 Windows 遥测：DiagTrack / CEIP / Spotlight / 广告 ID / 活动历史
  • 关闭 Windows 其他组件：Recall / Copilot / MDM / SysMain / WSearch / DO P2P
  • 关闭 Windows Defender：实时保护 / 云保护 / SmartScreen / 防火墙 ；仅供参考

子系统与运行时

  • WSL 2：Hyper-V 轻量虚拟机 + 完整 Linux 内核。NAT / mirrored / bridged 三种网络模式，mirrored 与外部 vSwitch 不兼容，见 WSL2 Mirrored 网络模式故障排查。装机参考 Ubuntu WSL Setup。
  • Hyper-V：Type-1 hypervisor，Pro 起可用。开启后 VBS / HVCI / Credential Guard 也依赖它。常见管理命令见 Hyper-V 常见命令。
  • Windows Sandbox：一次性 Win11 沙箱，关闭即清空，Pro 起可用。
  • Windows Containers：Process / Hyper-V isolation 两种模式，仅 Pro / Enterprise / Server。
  • .NET Framework（4.x，随系统）vs .NET（6 / 8 / 9，跨平台）：两套并存，老桌面软件仍依赖前者。
  • PowerShell 7 vs Windows PowerShell 5.1：前者跨平台 .NET，后者随系统出厂，补丁渠道独立。
  • UI 栈：Win32 / WinForms / WPF / UWP / WinUI 3 / MAUI 并存，跨代不兼容，是 Windows 桌面生态最大的历史包袱。

Windows 作为直连网关

直连设备先用 IPv4 link-local 找到对端，例如 Windows Ethernet 3 为 169.254.217.128/16，Ubuntu enp3s0 为 169.254.219.140/16。要让 Windows 给这条线上的 Ubuntu 提供 Internet，优先用 Internet Connection Sharing（ICS）。

ICS 通常会把直连网卡改成 192.168.137.1/24，并在这条线上提供 DHCP / DNS / NAT；Ubuntu 的地址会从 169.254.*.* 变成 192.168.137.x。

Windows GUI：

ncpa.cpl
  • 打开正在上网的网卡（例如 Wi-Fi）属性。
  • Sharing -> 勾选 Allow other network users to connect through this computer's Internet connection。
  • Home networking connection 选择直连网卡（例如 Ethernet 3）。

如果看不到 Home networking connection 下拉框，通常是 Windows 认为只有一个可共享的内部网卡，或者直连网卡当前不是可用连接：

  • 确认直连网线已插好，Ethernet 3 在 ncpa.cpl 里是 Enabled，不是 Disabled / Network cable unplugged。
  • 先取消 ICS 勾选并点 OK，重新打开正在上网的网卡属性，再勾选 ICS；有时 Windows 会自动选择唯一的内部网卡，因此不显示下拉框。
  • 如果有 Hyper-V / WSL / VPN 虚拟网卡，临时禁用不相关网卡后再打开 Sharing，避免 ICS 把候选网卡识别混乱。
  • 确认 SharedAccess 服务没有被禁用：
Get-Service SharedAccess
Set-Service SharedAccess -StartupType Manual
Start-Service SharedAccess
  • 勾选后检查直连网卡是否被改成 192.168.137.1/24；如果已经改好，就不需要再手动选择下拉框。

Windows PowerShell 重建 ICS，适合 GUI 找不到下拉框、USB 网卡重新枚举后 ICS 只留下 192.168.137.1、但 DHCP / DNS 没有真正启动的场景。需要管理员 PowerShell：

$publicName = "Wi-Fi"
$privateName = "Ethernet 3"

$share = New-Object -ComObject HNetCfg.HNetShare

function Get-IcsConnection {
    param([Parameter(Mandatory)] [string] $Name)

    foreach ($conn in $share.EnumEveryConnection()) {
        $props = $share.NetConnectionProps($conn)
        if ($props.Name -eq $Name) {
            return $conn
        }
    }

    throw "Connection not found: $Name"
}

Start-Service NlaSvc -ErrorAction SilentlyContinue

foreach ($conn in $share.EnumEveryConnection()) {
    $config = $share.INetSharingConfigurationForINetConnection($conn)
    if ($config.SharingEnabled) {
        $config.DisableSharing()
    }
}

Stop-Service SharedAccess -Force -ErrorAction SilentlyContinue
Remove-NetIPAddress -InterfaceAlias $privateName -IPAddress "192.168.137.1" -Confirm:$false -ErrorAction SilentlyContinue
Set-NetIPInterface -InterfaceAlias $privateName -AddressFamily IPv4 -Dhcp Enabled -ErrorAction SilentlyContinue
Start-Service SharedAccess

$share = New-Object -ComObject HNetCfg.HNetShare
$public = Get-IcsConnection $publicName
$private = Get-IcsConnection $privateName

# 0 = public / Internet side; 1 = private / home network side
$share.INetSharingConfigurationForINetConnection($public).EnableSharing(0)
$share.INetSharingConfigurationForINetConnection($private).EnableSharing(1)

PowerShell 验证：

Get-NetIPAddress -InterfaceAlias "Ethernet 3" -AddressFamily IPv4
Get-Service SharedAccess
Get-NetNeighbor -AddressFamily IPv4 -InterfaceAlias "Ethernet 3"
netstat -ano -p udp | findstr ":67"
netstat -ano -p udp | findstr ":53"

判断：

  • Ethernet 3 变成 192.168.137.1/24 只说明私网地址已写入，不代表 DHCP / DNS 已经工作。
  • SharedAccess 为 Running 也不够；需要看到 192.168.137.1:67，以及 DNS 监听（常见为 0.0.0.0:53）。
  • 如果只有 192.168.137.1:137/138/1900，没有 :67 / :53，Ubuntu 会卡在 getting IP configuration。

Ubuntu 端把直连网卡改回 DHCP：

sudo nmcli connection modify "Wired connection 2" \
    ipv4.method auto \
    ipv4.addresses "" \
    ipv4.gateway "" \
    ipv4.dns "" \
    ipv4.routes "" \
    ipv4.ignore-auto-dns no \
    ipv4.never-default no \
    ipv4.may-fail yes
sudo nmcli connection up "Wired connection 2" ifname enp3s0

验证：

ip -4 addr show enp3s0
ip route
ping 8.8.8.8
ping google.com

期望默认路由类似：

default via 192.168.137.1 dev enp3s0

之后从 Windows SSH 到 Ubuntu 使用新的 DHCP 地址：

ssh hobochen@192.168.137.x

手动 NAT 可保留自定义网段，但需要管理员 PowerShell，适合不想用 ICS 的场景：

New-NetIPAddress -InterfaceAlias "Ethernet 3" -IPAddress 192.168.50.1 -PrefixLength 24
Set-NetIPInterface -InterfaceAlias "Ethernet 3" -Forwarding Enabled
New-NetNat -Name "DirectUbuntuNat" -InternalIPInterfaceAddressPrefix 192.168.50.0/24

Ubuntu 静态配置示例：

sudo nmcli connection modify "Wired connection 2" \
    ipv4.method manual \
    ipv4.addresses 192.168.50.2/24 \
    ipv4.gateway 192.168.50.1 \
    ipv4.dns "1.1.1.1 8.8.8.8" \
    ipv4.never-default no
sudo nmcli connection up "Wired connection 2"
