Ubuntu Root on ZFS via ZBM

将 Ubuntu 新装到 ZFS，或把 USB 上的现有系统迁移到 SSD。目标为 x86-64 UEFI → ZFSBootMenu（ZBM）→ ZFS 根池，不依赖 GRUB。以下是命令骨架，供 AI 按实际机器补全；<…> 均为占位符，不能原样执行。

1. 磁盘与目标布局

从 Ubuntu Live 环境操作。迁移时关闭源系统，离线挂载复制；先确认目标盘可清除，保留源 USB。

sudo -i
lsblk -o NAME,SIZE,MODEL,SERIAL,FSTYPE,MOUNTPOINTS
findmnt
ls -l /dev/disk/by-id/
test -d /sys/firmware/efi && echo UEFI

# 单盘；mirror 时把第二块盘也加入 DISKS
DISKS=("/dev/disk/by-id/<目标盘>")
TARGET=/mnt/target
apt update
apt install -y gdisk parted dosfstools zfsutils-linux debootstrap rsync curl efibootmgr
modprobe zfs

预期：确认 Live、源盘与目标盘各是谁，当前为 UEFI 启动。目标布局：每块启动盘 512 MiB ESP，剩余空间用于 zroot；zroot/ROOT/ubuntu 挂载 /，zroot/home 挂载 /home。默认无加密、无 swap。

基础：ZBM 的启动方式、Ubuntu UEFI 安装参考。

2. 建池与数据集

以下分区命令清除 DISKS 中的磁盘。先核对实际型号、序列号和用途。

ROOT_PARTS=()
for disk in "${DISKS[@]}"; do
  sgdisk --zap-all "$disk"
  sgdisk -n 1:1m:+512m -t 1:ef00 -n 2:0:-10m -t 2:bf00 "$disk"
  partprobe "$disk"
  udevadm settle
  mkfs.vfat -F32 "${disk}-part1"
  ROOT_PARTS+=("${disk}-part2")
done

# 单盘留空；双盘设为 VDEV=(mirror)
VDEV=()
zpool create -R "$TARGET" -m none -o ashift=12 -o autotrim=on \
  -o compatibility="<与所选ZBM兼容的特性配置>" \
  -O compression=lz4 -O acltype=posixacl -O xattr=sa -O relatime=on \
  zroot "${VDEV[@]}" "${ROOT_PARTS[@]}"
zfs create -o mountpoint=none zroot/ROOT
zfs create -o mountpoint=/ -o canmount=noauto zroot/ROOT/ubuntu
zfs create -u -o mountpoint=/home zroot/home
zpool set bootfs=zroot/ROOT/ubuntu zroot
zfs mount zroot/ROOT/ubuntu
zfs mount zroot/home
zfs list

预期：根与 home 分别位于 $TARGET、$TARGET/home；mirror 应在 zpool status zroot 中显示两个成员。若已有同名池，先处理冲突，不强制覆盖。旧记录使用 openzfs-2.3-linux，实际值取决于 ZBM 内置 OpenZFS，不能保证对所有版本通用。

基础：池与 vdev、数据集与挂载属性。

3. 写入系统：二选一

新装 Ubuntu

debootstrap "<Ubuntu代号>" "$TARGET" https://archive.ubuntu.com/ubuntu/

预期：$TARGET 内有基础系统。随后在 chroot 中配置对应版本的软件源（含 universe）、主机名、locale、时区和账户；不复用历史内核版本号。

迁移 USB Ubuntu

先把源根分区只读挂到 /mnt/source。独立的 /home、/boot 等需分别挂载并复制；-x 不跨文件系统。

SOURCE=/mnt/source
mkdir -p "$SOURCE"
mount -o ro "/dev/disk/by-id/<源盘根分区>" "$SOURCE"
rsync -aHAXx --info=progress2 \
  --exclude='/dev/*' --exclude='/proc/*' --exclude='/sys/*' \
  --exclude='/run/*' --exclude='/tmp/*' --exclude='/mnt/*' \
  --exclude='/media/*' --exclude='/boot/efi/*' --exclude='/swap.img' \
  "$SOURCE/" "$TARGET/"

# 仅当源 /home 是独立文件系统时，另行挂载并复制
# rsync -aHAXx /mnt/source-home/ "$TARGET/home/"

预期：保留原账户、软件、文件权限、ACL 和扩展属性；数据写入目标 ZFS 数据集，源 USB 保持完整。运行中复制不能保证数据库等应用数据一致，最终同步应离线完成。

基础：debootstrap、rsync 参数。

4. 系统启动支持

新装生成 hostid；迁移复制源系统的 /etc/hostid（若存在），保证目标系统与 initramfs 一致。

# 新装示例；迁移有原 hostid 时改为复制原文件
test -s /etc/hostid || zgenhostid
cp /etc/hostid "$TARGET/etc/hostid"
mkdir -p "$TARGET/boot/efi"
mount "${DISKS[0]}-part1" "$TARGET/boot/efi"
blkid "${DISKS[0]}-part1"

将目标 /etc/fstab 的旧根与旧 home 条目移除，由 ZFS 管理挂载；ESP 使用刚读取的 UUID。其他数据盘挂载按需保留。

UUID=<目标ESP的UUID> /boot/efi vfat umask=0077 0 2
for dir in dev proc sys run; do
  mount --rbind "/$dir" "$TARGET/$dir"
  mount --make-rslave "$TARGET/$dir"
done
chroot "$TARGET" /bin/bash

# 以下在 chroot 内；先确保软件源与 DNS 可用
apt update
apt install -y linux-generic zfs-initramfs zfsutils-linux
# 仅新装桌面时：apt install -y ubuntu-desktop
# 仅新装账户时：adduser <用户名> && usermod -aG sudo <用户名>
zfs set org.zfsbootmenu:commandline="quiet splash" zroot/ROOT
update-initramfs -u -k all
exit

预期：目标有可启动内核、对应 ZFS 模块及 initramfs，迁移系统不再引用旧根分区或旧 swap。若需 swap，另建独立 swap 分区、mkswap 并按 UUID 写入 fstab，不使用 zvol；resume 按实际休眠需求配置。

基础：ZBM 数据集属性、ZFS 根文件系统。

5. 安装 ZBM 到 ESP

ESP="$TARGET/boot/efi"
mkdir -p "$ESP/EFI/ZBM" "$ESP/EFI/BOOT"
curl -fL https://get.zfsbootmenu.org/efi -o "$ESP/EFI/ZBM/VMLINUZ.EFI"
cp "$ESP/EFI/ZBM/VMLINUZ.EFI" "$ESP/EFI/BOOT/BOOTX64.EFI"
efibootmgr -c -d "${DISKS[0]}" -p 1 \
  -L ZFSBootMenu -l '\EFI\ZBM\VMLINUZ.EFI'

预期：ESP 有 ZBM 与 UEFI fallback 文件，固件有对应启动项。Secure Boot 需另行处理签名或关闭验证。mirror 的第二块盘也要复制 EFI/ 并注册启动项；ESP 不受 ZFS mirror 保护，今后更新也需同步。

基础：ZBM 预构建 EFI。

6. 重启后的结果

卸载本次 chroot 绑定挂载与 ESP，卸载目标数据集并 zpool export zroot，再重启并拔掉源 USB。不要全局卸载其他池。

findmnt --target /
findmnt --target /home
zpool status zroot
zpool get bootfs zroot

预期：ZBM 能启动 Ubuntu；/、/home 分别来自 zroot/ROOT/ubuntu、zroot/home；池 ONLINE，账户与文件可用。mirror 另外验证两盘各自可以引导。启动失败时保留源 USB，从 Live 环境检查池导入、hostid、initramfs 和 ESP。

需要独立镜像数据池时，另用两块明确可清除的数据盘创建 tank，不要把它们与根池成员混淆：

zpool create -m /mnt/mirror -o ashift=12 -O compression=lz4 \
  tank mirror "/dev/disk/by-id/<数据盘1>" "/dev/disk/by-id/<数据盘2>"
# 在目标系统中设置，并核对 zfs-import-cache 服务
zpool set cachefile=/etc/zfs/zpool.cache tank

预期：重启后 tank 自动导入并挂载 /mnt/mirror。日常快照、备份与维护见 ZFS。
