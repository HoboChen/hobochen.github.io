ZFS

OpenZFS on Linux 的日常查询、快照、复制与磁盘维护命令。

conventions

  • 存储池：tank
  • 数据集：tank/data
  • 快照：tank/data@snap
  • 块设备：优先使用 /dev/disk/by-id/...，不要直接使用 /dev/sdX
  • 修改前用 zpool status、zfs list 确认池、数据集和设备；试运行参数按各子命令说明使用，-v、-P 本身不阻止修改

status

pools

zpool status
zpool status -v tank
zpool list
zpool list -v
zpool get all tank

datasets

zfs list
zfs list -r tank
zfs list -o name,used,avail,refer,mountpoint,compression
zfs get all tank/data

space

zfs list -o space -r tank
zfs list -t snapshot -o name,used,refer,creation -r tank/data
zpool list -o name,size,alloc,free,cap,health

io

zpool iostat
zpool iostat -v tank 1

请求大小与延迟直方图分别查询，-r 与 -w 互斥；持续输出用 Ctrl+c 停止：

zpool iostat -r tank 1
zpool iostat -w tank 1

maintenance schedule

  • 每周：zpool status，确认 ONLINE 且无 checksum / read / write error。
  • 每月：zpool scrub tank，完成后查看 zpool status tank。
  • 每次换盘：使用 /dev/disk/by-id，替换后等待 resilver 完成。
  • 每次大升级：先做递归快照，关键数据再做异机复制。
  • 每次扩容：先确认 vdev 拓扑；不要把单盘 vdev 误加进冗余池。

dataset management

create dataset

sudo zfs create tank/data
sudo zfs create -o mountpoint=/srv/data tank/data

destroy dataset

先预览递归删除范围；-n 阻止实际删除，-v 显示明细：

sudo zfs destroy -nvr tank/data

确认后按需选择一种：不带 -r 只删除当前数据集，存在子数据集或快照时会拒绝；带 -r 删除它及其子数据集和快照。

sudo zfs destroy tank/data
sudo zfs destroy -r tank/data

rename dataset

sudo zfs rename tank/data tank/archive
sudo zfs rename tank/data tank/parent/data

mount and unmount

sudo zfs mount tank/data
sudo zfs mount -a
sudo zfs unmount tank/data
sudo zfs unmount -a

mountpoint

sudo zfs set mountpoint=/srv/data tank/data
sudo zfs set mountpoint=legacy tank/data
sudo zfs set mountpoint=none tank/data

properties

compression

sudo zfs set compression=lz4 tank/data
sudo zfs set compression=zstd tank/data
zfs get compression,compressratio tank/data

access time

完全关闭访问时间更新：

sudo zfs set atime=off tank/data

若需要保留访问时间，改用相对更新；relatime 仅在 atime=on 时生效：

sudo zfs set atime=on relatime=on tank/data

xattr and acl

sudo zfs set xattr=sa tank/data
sudo zfs set acltype=posixacl tank/data

quota and reservation

sudo zfs set quota=2T tank/data
sudo zfs set refquota=1T tank/data
sudo zfs set reservation=500G tank/data
sudo zfs set refreservation=200G tank/data

zfs get quota,refquota,reservation,refreservation tank/data
  • quota 限制数据集及子数据集总占用。
  • refquota 只限制当前数据集自身可引用空间。
  • reservation 为数据集及子数据集预留空间。
  • refreservation 只为当前数据集预留空间。

autotrim

sudo zpool set autotrim=on tank
zpool get autotrim tank

autoexpand

sudo zpool set autoexpand=on tank
zpool get autoexpand tank

snapshots

create snapshot

sudo zfs snapshot tank/data@before-upgrade
sudo zfs snapshot -r tank@daily-2026-06-26

list snapshots

zfs list -t snapshot
zfs list -t snapshot -r tank/data
zfs list -t snapshot -o name,used,refer,creation -s creation

destroy snapshot

先用 sudo zfs destroy -nv tank/data@before-upgrade 预览；递归同名快照则用 sudo zfs destroy -nvr tank@daily-2026-06-26。确认后选择对应删除命令：

sudo zfs destroy tank/data@before-upgrade
sudo zfs destroy -r tank@daily-2026-06-26

rollback

sudo zfs rollback tank/data@before-upgrade
sudo zfs rollback -r tank/data@before-upgrade
  • rollback 会丢弃快照之后的变更。
  • -r 会删除当前数据集上比目标更新的快照及书签，不表示递归回滚子数据集；rollback 不提供 -n 试运行。

diff

zfs diff tank/data@before tank/data@after
zfs diff tank/data@before

restore file

ls /tank/data/.zfs/snapshot/before-upgrade
cp /tank/data/.zfs/snapshot/before-upgrade/file ./file.restore

clones

create clone

sudo zfs clone tank/data@before-upgrade tank/data-test

promote

sudo zfs promote tank/data-test

promote 反转依赖关系：原数据集 tank/data 成为克隆，共享的起始快照及更早快照归 tank/data-test 所有。它不复制数据块，也不生成一份独立备份。

destroy clone

sudo zfs destroy tank/data-test

scrub and errors

start scrub

sudo zpool scrub tank

scrub progress

zpool status tank

stop scrub

sudo zpool scrub -s tank

clear errors

sudo zpool clear tank
sudo zpool clear tank /dev/disk/by-id/DISK_ID

zpool clear 只清错误计数，不修复坏盘或坏数据。

disk maintenance

device ids

ls -la /dev/disk/by-id/ | grep -v part

offline disk

sudo zpool offline tank /dev/disk/by-id/OLD_DISK

online disk

sudo zpool online tank /dev/disk/by-id/OLD_DISK

replace disk

sudo zpool replace tank /dev/disk/by-id/OLD_DISK /dev/disk/by-id/NEW_DISK
watch -n 5 zpool status tank

expand disk

sudo zpool online -e tank /dev/disk/by-id/DISK_ID
zpool list tank

add mirror vdev

zpool add 支持 -n 预览。添加的是新顶层 vdev，不是给现有单盘补 mirror：

sudo zpool add -n tank mirror /dev/disk/by-id/DISK3 /dev/disk/by-id/DISK4
sudo zpool add tank mirror /dev/disk/by-id/DISK3 /dev/disk/by-id/DISK4

添加 vdev 通常不可逆；扩容前先确认拓扑。

add l2arc

sudo zpool add tank cache /dev/disk/by-id/CACHE_DISK

add slog

sudo zpool add tank log mirror /dev/disk/by-id/SLOG1 /dev/disk/by-id/SLOG2

remove l2arc and slog

sudo zpool remove tank /dev/disk/by-id/CACHE_DISK
sudo zpool remove tank /dev/disk/by-id/SLOG1

import and export

discover pools

sudo zpool import

import pool

sudo zpool import tank
sudo zpool import -d /dev/disk/by-id tank

alternate root

sudo zpool import -R /mnt tank

import without mounting

sudo zpool import -N tank
sudo zfs mount tank/data

export pool

sudo zpool export tank

force import

sudo zpool import -f tank

只在确认池没有被另一台机器同时使用时执行。

replication

full send

以下示例使用已有的 backup 池，接收目标 backup/data 尚不存在。-u 禁止自动挂载，避免复制来的挂载点与源端冲突。

sudo zfs snapshot -r tank/data@backup-001
sudo zfs send -R tank/data@backup-001 | sudo zfs recv -u backup/data

stream file

sudo zfs send -R tank/data@backup-001 > tank-data-backup-001.zfs
sudo zfs recv -u backup/data < tank-data-backup-001.zfs

incremental send

sudo zfs snapshot -r tank/data@backup-002
sudo zfs send -R -i tank/data@backup-001 tank/data@backup-002 | sudo zfs recv -u backup/data

ssh replication

接收端需有 backup 池，SSH 用户需能非交互执行相应的 sudo zfs recv；完整发送与增量发送按需选择：

sudo zfs send -R tank/data@backup-001 | ssh user@backup-host sudo -n zfs recv -u backup/data
sudo zfs send -R -i tank/data@backup-001 tank/data@backup-002 | ssh user@backup-host sudo -n zfs recv -u backup/data

force receive

sudo zfs recv -uF backup/data < tank-data-backup-001.zfs

-F 会回滚接收端目标数据集；接收递归增量流时，还可能删除源端不存在的快照和文件系统。执行前确认接收端没有需要保留的新数据。

restore test

在接收端选择一个已收到的快照创建测试克隆，显式指定挂载点：

sudo zfs clone -o mountpoint=/mnt/zfs-restore-test \
  backup/data@backup-001 backup/restore-test
ls /mnt/zfs-restore-test

确认文件可读后删除测试克隆：

sudo zfs destroy backup/restore-test

backup checklist

encryption

create encrypted dataset

sudo zfs create -o encryption=on \
  -o keyformat=passphrase \
  -o mountpoint=/secure \
  tank/secure

load key

sudo zfs load-key tank/secure
sudo zfs mount tank/secure

unmount and unload key

sudo zfs unmount tank/secure
sudo zfs unload-key tank/secure

key status

zfs get encryption,keyformat,keystatus tank/secure

create pool

zpool create 支持 -n 预览拓扑，不创建池。先检查预览，再选择下方一种拓扑创建：

sudo zpool create -n -o ashift=12 tank mirror \
  /dev/disk/by-id/DISK1 /dev/disk/by-id/DISK2

single disk

sudo zpool create -o ashift=12 \
  -O compression=lz4 \
  -O atime=off \
  -O xattr=sa \
  -O acltype=posixacl \
  -m /tank \
  tank /dev/disk/by-id/DISK_ID

mirror

sudo zpool create -o ashift=12 \
  -O compression=lz4 \
  -O atime=off \
  -m /tank \
  tank mirror \
  /dev/disk/by-id/DISK1 \
  /dev/disk/by-id/DISK2

raidz2

sudo zpool create -o ashift=12 \
  -O compression=lz4 \
  -O atime=off \
  -m /tank \
  tank raidz2 \
  /dev/disk/by-id/DISK1 \
  /dev/disk/by-id/DISK2 \
  /dev/disk/by-id/DISK3 \
  /dev/disk/by-id/DISK4 \
  /dev/disk/by-id/DISK5 \
  /dev/disk/by-id/DISK6

slog and l2arc

sudo zpool create -o ashift=12 \
  -O compression=lz4 \
  -O atime=off \
  -m /tank \
  tank raidz2 \
  /dev/disk/by-id/DISK1 /dev/disk/by-id/DISK2 \
  /dev/disk/by-id/DISK3 /dev/disk/by-id/DISK4 \
  log mirror /dev/disk/by-id/SLOG1 /dev/disk/by-id/SLOG2 \
  cache /dev/disk/by-id/L2ARC1
  • log 是 SLOG，只加速同步写入，不是普通写缓存。
  • cache 是 L2ARC，掉盘不影响池数据。
  • SLOG 建议使用带掉电保护的低延迟 SSD，并做 mirror。

destroy pool

删除整个池及其所有数据；zpool destroy 不提供 -n 试运行。

zpool status -P tank
zfs list -r tank

确认目标后单独执行：

sudo zpool destroy tank

installation

debian and ubuntu

sudo apt update
sudo apt install -y zfsutils-linux
zfs version

services

systemctl status zfs-import-cache.service
systemctl status zfs-mount.service
systemctl status zfs-zed.service

destructive operations

  • 删除：数据集、快照、整池；试运行支持见各节。
  • 覆盖现有数据：回滚快照、接收端覆盖。
  • 改变拓扑：添加 vdev、替换磁盘；先核对目标设备与冗余。

troubleshooting

automatic import

sudo zpool import
sudo zpool import -d /dev/disk/by-id tank
sudo zpool set cachefile=/etc/zfs/zpool.cache tank
sudo systemctl enable zfs-import-cache.service zfs-mount.service zfs-zed.service

dataset not mounted

zfs get mounted,mountpoint,canmount tank/data
sudo zfs mount tank/data
sudo zfs mount -a

pool in use

sudo zpool import
sudo zpool import -f tank

确认旧系统已经关机或池已经导出后再强制导入。

device paths

sudo zpool export tank
sudo zpool import -d /dev/disk/by-id tank
zpool status tank

read only import

sudo zpool import -o readonly=on -R /mnt tank

events

zpool events
zpool events -v
journalctl -u zfs-zed.service
