域名接入、代理模式与证书、Zero Trust 相关。

add domain to cloudflare

两种方案：只改 nameserver，或连注册商一起转移。只用 Proxy / Zero Access / DNS 时，nameserver 接入即可。

方案 A：nameserver 接入

  1. 在 Cloudflare 添加域名，获取 Cloudflare 分配的 nameservers
  2. 检查导入的 DNS 记录：A / CNAME / MX / TXT / SPF / DKIM / DMARC
  3. Namecheap -> Domain List -> Manage -> Domain -> Nameservers，改为 Cloudflare nameservers
  4. 回到 Cloudflare 等待验证生效
  5. 如已启用 DNSSEC，切换后重新配置

结果：DNS、Proxy、Tunnel、Zero Trust 交给 Cloudflare；注册和续费仍在 Namecheap。

方案 B：转移注册商到 Cloudflare

前提：先完成方案 A。

  1. Cloudflare -> Transfer Domains 发起转移
  2. Namecheap 解锁域名
  3. 获取 Auth / EPP code
  4. 确认续费和到期状态

限制：

  • 注册后或最近一次转移后 60 天内不能转移
  • 最近修改 WHOIS / registrant 信息也可能触发 60 天限制

proxy mode

origin certificate

Cloudflare Origin CA 只用于 Cloudflare edge -> 源站，不在公共 CA 信任链中。浏览器直连源站会报 SEC_ERROR_UNKNOWN_ISSUER。

开启橙云后：

flowchart LR
    A[浏览器] -->|edge cert| B[Cloudflare]
    B -->|origin cert| C[源站]
  • 橙云开启：用户看到 Cloudflare edge certificate
  • 灰云 / 直连源站：用户看到源站 origin cert，不受信则报错

Let’s Encrypt 作为源站证书

Let’s Encrypt 同时适合 Cloudflare 回源和浏览器直连，比 Origin CA 更灵活。

注意：

  • Cloudflare SSL 模式：Full (strict)
  • Nginx 使用 fullchain.pem，不是 cert.pem
  • 申请方式见 proxy mode and https

橙云对 Let’s Encrypt 自动续期的影响

验证方式 橙云影响 结论
DNS-01 不受影响 推荐
HTTP-01 可能受 Always Use HTTPS / WAF 影响 不推荐

proxy mode and https

橙云开启后，HTTP 流量经过 Cloudflare，源站 IP + 端口不再适合 HTTP-01。证书申请优先用 DNS-01。

DNS-01 验证原理

DNS-01 通过 _acme-challenge.<domain> TXT 记录证明 DNS 控制权。

方式 控制对象 要求
HTTP-01 服务器 80 端口公网可达
DNS-01 DNS 不需要公网直连源站

DNS-01 支持通配符证书。

acme.sh + Cloudflare DNS API 配置

创建 Cloudflare API Token

权限：

  • Zone / DNS / Edit
  • Zone / Zone / Read

安装与签发

curl https://get.acme.sh | sh

export CF_Token="your_token"
export CF_Account_ID="your_account_id"
export CF_Zone_ID="your_zone_id"

acme.sh --issue --dns dns_cf -d intra.example.com
acme.sh --issue --dns dns_cf -d example.com -d '*.example.com'

安装证书到 Nginx

acme.sh --install-cert -d intra.example.com \
  --key-file /etc/nginx/ssl/privkey.pem \
  --fullchain-file /etc/nginx/ssl/fullchain.pem \
  --reloadcmd "systemctl reload nginx"

Nginx：

ssl_certificate     /etc/nginx/ssl/fullchain.pem;
ssl_certificate_key /etc/nginx/ssl/privkey.pem;

acme.sh 会注册 cron，续期后执行 --reloadcmd。

zero trust

Cloudflare Zero Trust 常用两部分：

  • Tunnel：内网服务主动连 Cloudflare，不需要公网 IP / 入站端口
  • Access：访问控制，支持登录、MFA、邮箱域名、国家/地区、设备等策略

tunnel

cloudflared 只建立出站连接。

flowchart LR
    A[localhost:3000] --> B[Cloudflare Tunnel]
    B --> C[Access 登录页]
    C --> D[受控访问]
  • 域名 app.example.com 指向 tunnel
  • 用户先过 Access，再转发到本地服务
  • 高并发可增加 replicas 或拆分 tunnels

收费

功能 费用
Tunnel 免费 plan 可用
Quick Tunnel 临时测试；200 并发限制；不支持 SSE
Access Free 50 用户以下
Access Pay-as-you-go $7 / 用户 / 月，按年付

个人 / 小团队通常 Free 足够。

zero trust and pwa

问题：Access 会拦截 manifest.json、Service Worker、icons，浏览器拿到登录页 HTML，PWA 无法安装。

原因：浏览器获取这些资源时不带 CF_Authorization cookie。

处理：为静态资源单独建 Bypass Application，优先级放在主应用上方。

典型路径：

  • /manifest.json
  • /sw.js
  • /icons/*

配置：

  1. Zero Trust -> Access -> Applications -> Add an application -> Self-hosted
  2. Application domain：主应用同域名
  3. Path：需要放行的静态资源路径
  4. Policy：Action = Bypass，Include = Everyone
  5. Applications 列表中拖到主应用上方
