x86 OpenWrt 软路由配置笔记。

安装

镜像选择

使用 Firmware Selector 构建镜像；需要额外网卡驱动时，把包直接打进镜像。

启动方式 文件系统 镜像
UEFI ext4 generic-ext4-combined-efi.img.gz
UEFI squashfs generic-squashfs-combined-efi.img.gz
Legacy BIOS ext4 generic-ext4-combined.img.gz
Legacy BIOS squashfs generic-squashfs-combined.img.gz
  • ext4：像普通 Linux，根分区可写，适合 x86。
  • squashfs：更像传统路由器，支持 factory reset。

写盘必须写入整盘，不是分区：

gzip -dc openwrt-25.12.1-x86-64-generic-ext4-combined-efi.img.gz \
  | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync

扩容

ext4 离线扩容最稳。把盘接到另一台 Linux / LiveCD / VM：

parted /dev/sdX
# print -> resizepart 2 100% -> quit

e2fsck -f /dev/sdX2
resize2fs /dev/sdX2

启动后检查：

df -h

squashfs + overlay 走另一套流程，见 OpenWrt expand root。

首次配置

  • 默认地址：http://192.168.1.1
  • 用户：root
  • 默认密码：空

检查项：

  1. 设置 root 密码
  2. 确认 WAN/LAN 物理口顺序
  3. 配置 WAN：DHCP / PPPoE / static

x86 机器的接口名和机身标签经常不一致，先确认再接入主网络。

常用命令

poweroff    # shutdown
reboot      # restart
logread     # logs
logread -f  # follow logs
df -h       # disk usage
free        # memory
top         # processes

交换 LAN / WAN

DSA 下，端口角色由配置决定：在 br-lan 里的是 LAN，绑定到 wan interface 的是 WAN。

LuCI

把原 WAN 改成 LAN，把 lan4 改成 WAN：

  1. Network -> Devices -> br-lan：移除 lan4，加入原 wan
  2. Network -> Interfaces -> WAN：绑定到 lan4
  3. WAN6：同样重绑，或删除重建

CLI

cp /etc/config/network /etc/config/network.bak

uci del network.wan
uci del network.wan6
uci del_list network.br_lan.ports='lan4'
uci add_list network.br_lan.ports='wan'
uci set network.wan=interface
uci set network.wan.proto='dhcp'
uci set network.wan.device='lan4'
uci commit network
/etc/init.d/network restart

操作时保留 SSH 会话，避免改错后失联。

有 IP 但不能上网

排查顺序：

  1. OpenWrt 自己是否能上网
ip addr
ip route
ping -c 4 223.5.5.5
  1. WAN 是否绑到正确端口
uci show network | grep -E "network\.(wan|wan6|lan|br_lan)"

同一物理口不能同时属于 br-lan 和 wan。

  1. WAN 是否拿到上游地址
ifstatus wan
logread | grep -i dhcp
  1. NAT 是否生效
uci show firewall | grep -E "zone.*wan|masq|network"
fw4 check 2>&1
nft list chain inet fw4 srcnat_wan

常见判断：

现象 方向
ifstatus wan 无地址 端口绑定 / 上游 DHCP / PPPoE / static
无 default route WAN 未真正起来
OpenWrt 能上网，客户端不能 firewall / NAT
uci show 正常但 NAT 不工作 fw4 加载失败，例如 Docker 规则冲突

DDNS

Cloudflare DDNS 用内置 ddns-scripts，推荐 API Token。

安装

apk update && apk add luci-app-ddns ddns-scripts ddns-scripts-cloudflare ca-bundle ca-certificates

旧版 OpenWrt 19.07 包名可能是 ddns-scripts_cloudflare.com-v4。

Token 权限

  • Zone / Zone / Read
  • Zone / DNS / Edit
  • Resource：指定 zone

关键配置

config service 'cloudflare_example'
    option enabled '1'
    option service_name 'cloudflare.com-v4'
    option lookup_host 'home.example.com'
    option domain 'home@example.com'
    option username 'Bearer'
    option password 'your_API_Token'
    option use_https '1'
    option cacert '/etc/ssl/certs'
    option ip_source 'network'
    option ip_network 'wan'
    option interface 'wan'
    option check_interval '5'
    option check_unit 'minutes'
    option force_interval '120'
    option force_unit 'minutes'
    option use_api_check '1'

注意：

  • domain 用 host@zone：home@example.com 更新 home.example.com。
  • lookup_host 用完整 FQDN。
  • DNS 记录必须已存在；脚本只更新，不创建。
  • 开橙云时必须设 use_api_check '1'，否则 DNS 查询拿到的是 Cloudflare edge IP。
  • interface 'wan' 控制 hotplug/ifup 事件，通常保留。
  • CA 证书路径：/etc/ssl/certs 或 /etc/ssl/certs/ca-certificates.crt。

IP 来源：

ip_source 配置 场景
network ip_network 'wan' 单 WAN，最常用
interface ip_interface 'wan' 按设备名取地址；必须显式设置
web ip_url 'https://api.ipify.org' WAN 是内网 / CGNAT 地址

DDNS 排错

/etc/init.d/ddns restart
logread -e ddns
tail -n 20 /var/log/ddns/cloudflare_example.log

Token 测试：

curl -sS \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  "https://api.cloudflare.com/client/v4/zones?name=example.com"

常见问题：

  • ip_interface not set for source interface：ip_source 选了 interface 但没设 ip_interface；改用 network 或 web。
  • Invalid access token：token 无效、过期、撤销或泄露后被 Cloudflare 自动撤销。
  • IP 一直 mismatch：开了橙云但没设 use_api_check。
  • Provider 不在下拉框：没装 ddns-scripts-cloudflare。

Metrics

标准链路：OpenWrt -> Prometheus -> Grafana。

OpenWrt：

apk update
apk add prometheus-node-exporter-lua
apk add prometheus-node-exporter-lua-wifi      # optional
apk add prometheus-node-exporter-lua-thermal   # optional
apk add prometheus-node-exporter-lua-textfile  # optional

curl http://192.168.1.1/metrics

Prometheus：

scrape_configs:
  - job_name: 'openwrt'
    metrics_path: /metrics
    static_configs:
      - targets: ['192.168.1.1:80']

Grafana 连接 Prometheus，不是直接连 OpenWrt。容器内的 localhost 指容器自己。

验证：

up{job="openwrt"}

返回 1 即正常。

SQM / QoS

推荐默认组合：CAKE + piece_of_cake.qos。

apk update && apk add luci-app-sqm sqm-scripts

LuCI：Network -> SQM QoS。

基本配置：

  • Interface：实际 WAN，DHCP/static 通常是 wan，PPPoE 通常是 pppoe-wan
  • Queue Discipline：cake
  • Queue Setup Script：piece_of_cake.qos
  • Download / Upload：实测带宽的 90%，单位 kbit/s
  • Link Layer Adaptation：不清楚封装就先默认

SQM 要把瓶颈拉回路由器，所以带宽必须略低于实际带宽。

Offloading

使用 SQM 时关闭 offloading：

场景 Software Offload Hardware Offload
SQM OFF OFF
不用 SQM，普通 NAT ON OFF
不用 SQM，CPU 瓶颈且确认支持 ON ON，需测试

只安装 SQM 包不影响 NAT 性能；启用 SQM 实例才有性能成本。提前关闭 flow offloading 会降低 NAT 吞吐。

调参

  1. 先测 baseline
  2. 启用 CAKE + piece_of_cake.qos + 90% 带宽
  3. 延迟仍高：90% -> 88% -> 85%
  4. 上传更敏感，优先保守

需要 DiffServ 优先级时再换 layer_cake.qos。避免 cake_mq，部分 OpenWrt 版本有吞吐问题。

常见问题：

  • SQM 绑错 interface
  • 带宽设太高
  • flow offloading 没关
  • CPU 跑不动高带宽 CAKE
  • PPPoE / VLAN overhead 配错

UPnP

OpenWrt 使用 miniupnpd，LuCI 包是 luci-app-upnp。

apk update && apk add miniupnpd luci-app-upnp
/etc/init.d/miniupnpd enable
/etc/init.d/miniupnpd restart

推荐配置：

  • Enable UPnP service：on
  • Enable secure mode：on
  • Internal interface：lan
  • External interface：wan / pppoe-wan

CLI：

uci set upnpd.config.enabled='1'
uci set upnpd.config.secure_mode='1'
uci set upnpd.config.internal_iface='lan'
uci set upnpd.config.external_iface='wan'
uci commit upnpd
/etc/init.d/miniupnpd restart

限制：

  • 只适合可信 LAN
  • secure mode 保持开启
  • 双 NAT / CGNAT 下，映射到不了公网
  • 不需要就关

检查：

logread | grep miniupnpd

apk failure

OpenWrt 25.12 源默认 HTTPS；如果镜像里是 wget-nossl，apk update 可能报：

wget: exited with error 1
unexpected end of file

推荐在构建镜像时换成 wget-ssl：

make image PROFILE="..." PACKAGES="wget-ssl -wget -wget-nossl"

已装好的系统可临时把源切到 HTTP：

sed -i 's#https://downloads.openwrt.org#http://downloads.openwrt.org#g' /etc/apk/repositories.d/distfeeds.list
apk update

Docker

zone duplicate definition

现象：firewall 重启失败，出现 docker_devices symbol redefinition。

原因：Docker zone 被定义了两次，一个匿名 zone，一个命名 zone。

检查：

uci show firewall | grep -i docker

如果同时看到 firewall.@zone[N] 和 firewall.docker，删掉重复项：

uci delete 'firewall.@zone[2]'
uci commit firewall
/etc/init.d/firewall restart

第一次重启可能出现一次性残留错误，再重启会消失。

containers have no internet

现象：容器无法访问外网。

原因：DOCKER-USER 中的 REJECT 规则过宽，挡住了容器主动连接的回包。

修复：

uci set 'dockerd.firewall.extra_iptables_args=--match conntrack ! --ctstate RELATED,ESTABLISHED'
uci commit dockerd
/etc/init.d/dockerd restart

验证：

iptables -L DOCKER-USER -v -n --line-numbers
docker run --rm alpine ping -c 3 8.8.8.8
